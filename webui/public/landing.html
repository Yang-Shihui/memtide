给 Agent 一颗
长期记忆

Memtide 是一个核心零第三方 SDK 的 agent 记忆引擎——原子事实抽取、预测编码门控、 混合检索、双时标审计、多模态记忆，PostgreSQL + Qdrant 生产栈开箱即用。

打开控制台 查看快速开始
python — memtide quickstart
# 任意 OpenAI 兼容端点（GLM / Qwen / OpenAI / vLLM ...）
from memtide import MemoryEngine, MemoryConfig

mem = MemoryEngine(MemoryConfig(
    pg_dsn="postgresql://memtide:pw@localhost:5432/memtide",
    llm_base_url="http://your-llm-endpoint/v1", llm_model="glm-5.3-flash",
    llm_api_key="sk-...", embedding_backend="dashscope",
    dashscope_api_key="sk-..."))
mem.add("我叫李雷，住在杭州，喜欢喝美式咖啡", user_id="alice")
mem.add("我搬到上海了", user_id="alice")   # 旧值自动进审计日志

mem.search("用户住哪", user_id="alice")  # → 混合检索，得分可解释
FEATURES

六种记忆机制，一个引擎

融合 Mem0 / Letta / Zep / LangMem 的核心设计，外加两个原创机制（预测编码门控、多模态溯源）。

原子事实 + 冲突消解

记忆是原子事实而非聊天记录。写时 LLM 决策 ADD / UPDATE / DELETE / NOOP——"搬到上海"会替换"住在杭州"，旧值进审计而非留下矛盾。

预测编码门控

记忆库即生成式先验：完全被预测到的事实不编码，越意外的记忆重要度越高（S = −log₂ p̂ 三分流）。记忆库越用越小、越用越准。

混合检索，得分可解释

向量余弦 + BM25 全文 + 实体索引三路召回，加权 RRF 融合后按语义相似/留存度/重要度重打分（可选 cross-encoder 重排与 MMR 多样性）。每条命中都带得分明细。

遗忘曲线 + 后台反思

Ebbinghaus 遗忘曲线：越少访问越快淡忘，被再次查询即"复忆"。开启 MEMTIDE_AUTO_REFLECT 后定期反思（或手动触发）把同主题簇蒸馏成概括，概括比细节忘得慢。

双时标审计

失效不删除：valid_at / invalid_at 双时标 + superseded_by 取代链 + 全量事件日志（ADD→UPDATE→ACCESS），历史完全可回放。

多模态记忆

图片 / 音频 / 文件以 OpenAI content-parts 直进管线：视觉模型转文字描述走完整管线，原始字节 sha256 内容寻址存储，文字查询即可跨模态召回。

ARCHITECTURE

写入五阶段，读取三路融合

所有决策可观测：每次写入返回逐条门控与消解决策，每次检索返回得分成分。

写入 messages ─▶ 多模态归一化 ─▶ 事实抽取 ─▶ 预测编码门控 ─▶ 冲突消解 ─▶ ADD / UPDATE / DELETE / NOOP │ S = −log₂ p̂ 三分流 旧值进审计链 ▼ 附件 sha256 内容寻址落盘 ◀────────────────────────────┘ 读取 query ──▶ ┌ 向量余弦(top-40) ┐ ├ BM25 全文 ├──▶ RRF 融合 ─▶ + 留存度 + 重要度 ─▶ 每次命中强化记忆 └ 实体索引匹配 ┘ 存储 PostgreSQL(BM25) ＋ Qdrant ANN
DEPLOY

从 pip 安装到生产栈

bash — docker compose
# 生产部署：PostgreSQL 16 + Qdrant + REST + 可视化控制台
git clone https://github.com/Yang-Shihui/memtide && cd memtide
cp .env.example .env          # 填入 LLM / embedding key
docker compose up -d --build

# 控制台  http://localhost:8300/console
# REST    http://localhost:8300/memories  ·  /search  ·  /stats
